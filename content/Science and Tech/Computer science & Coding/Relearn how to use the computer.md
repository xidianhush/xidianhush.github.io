# 挂起状态与页面置换机制

## 挂起状态（Suspended）
挂起是指程序运行被暂停，但其**内存内容仍保留在 RAM 中**，不会被移出到磁盘。主要特点如下：
- **挂起的作用**：
  - 减少 CPU 和 I/O 资源占用。
  - 数据仍保存在内存中，便于程序快速恢复运行。
- **与页面置换的区别**：
  - 挂起仅暂停程序的执行，但不会将数据移到磁盘。
  - 页面置换则会将程序的部分或全部内存数据写入磁盘。

### 例子：
假设 Google Chrome 被挂起：
- **挂起状态**：进程停止执行，但浏览器标签页的数据仍保留在内存中，方便快速恢复。
- **未触发页面置换**：数据未被写入磁盘，因此内存占用仍显示较高。

---

## 页面置换（Swapping）
页面置换是当系统内存不足时，将程序的数据从内存写入磁盘的机制。主要特点如下：
- **触发条件**：
  - 系统内存不足时，低优先级的程序会被置换到磁盘。
- **影响**：
  - 释放了内存，但程序恢复速度变慢，因为需要从磁盘重新加载数据。

### 页面置换的流程：
1. 操作系统识别低优先级的进程。
2. 将进程的部分或全部数据写入**虚拟内存（Pagefile）**。
3. 程序需要运行时，从磁盘重新加载到内存。

---

## 挂起和页面置换的比较

| **机制**       | **挂起（Suspended）**                | **页面置换（Swapping）**              |
|----------------|-------------------------------------|--------------------------------------|
| **是否释放内存** | 不释放内存，数据保留在 RAM 中          | 将数据写入磁盘，释放内存              |
| **恢复速度**    | 恢复快速，因数据保存在内存中           | 恢复较慢，需要从磁盘重新加载数据        |
| **触发条件**    | 操作系统为了节省 CPU 或 I/O 资源       | 系统内存资源不足时                    |
| **影响**       | 数据不受损，但程序暂停运行             | 数据移到磁盘，恢复时影响性能            |

---

## 总结
1. **挂起状态**：程序暂停运行，但数据仍在内存中，以保证快速恢复。
2. **页面置换**：当内存不足时，数据被写入磁盘，释放内存但降低恢复速度。
3. **两者区别**：
   - 挂起是节省 CPU 资源的优化策略；
   - 页面置换是内存不足时的必备机制。

# 电脑主机名(hostname)和用户名(username)
+ 例子：
	我的主机名（给电脑起的名字叫hush_computer，但是可以给很多人用，在下面设置用户名Administrator”“User1那些
+ 解释：
	是的，通常情况下一个电脑只有一个主机名（hostname），但可以有多个用户名（username）。下面来详细解释一下：
	一、主机名（hostname）
	1.  唯一性
	•  在一个网络环境中，一个电脑通常只有一个主机名。这个主机名在整个网络范围内应该是唯一的，这样才能确保网络中的其他设备能够准确地识别和找到这台电脑。例如，在一个公司的局域网中，如果两台电脑有相同的主机名，那么当其他设备尝试通过主机名与其中一台电脑通信时，就会出现混淆，不知道到底是要连接哪一台电脑。
	2.  特殊情况
	•  虽然一般情况下一台电脑只有一个主机名，但在一些特殊的技术场景下，可能会出现例外。比如在虚拟化技术中，一台物理主机上可以运行多个虚拟机，每个虚拟机可以有自己的主机名。从虚拟机的角度看，每个虚拟机就像是一台独立的电脑，有自己的主机名。但从物理主机的角度看，物理主机本身也有一个主机名。不过这种情况比较特殊，并不是传统意义上的一台普通电脑拥有多个主机名。
	二、用户名（username）
	1.  多用户支持
	•  一个电脑可以有多个用户名，这是现代操作系统多用户设计的体现。以Windows操作系统为例，一个家庭电脑可以有爸爸的用户账户、妈妈的用户账户和孩子的用户账户，每个账户都有自己的用户名。这样不同的家庭成员可以使用同一个电脑，但有自己的个性化设置，如桌面背景、文件存储位置等。
	•  在Linux系统中，多用户支持也是非常常见的。例如，在一个服务器上，可以有系统管理员账户、普通用户账户、开发者账户等多种用户账户，每个账户都有不同的用户名和权限。这种多用户机制可以满足不同用户在同一个系统上的工作和使用需求，同时还能保证用户之间的数据和操作相对独立。
	2.  应用场景
	•  多用户名在很多场景下都非常有用。在企业环境中，员工可以使用自己的用户名登录公司电脑，访问自己有权访问的文件和资源，同时保证公司的数据安全和保密性。在教育机构中，老师和学生可以使用不同的用户名登录学校的电脑系统，老师可以进行教学资源的管理和发布，学生可以使用自己的用户名访问学习资料和提交作业。
	所以，一个电脑只有一个主机名，但可以有多个用户名，这是由它们在网络和操作系统中的不同功能和设计目的所决定的。
	•  administrator”代表“管理员”。它是一个具有最高权限的用户账户
+ 不同用户的软件是否冲突以及C盘一些文件意义
	当电脑登录不同的用户名时，操作系统本身是相同的，但不同用户账户下的软件安装情况和操作环境可能会有所不同。以下是具体分析：
	一、操作系统层面
	•  操作系统是电脑的核心软件系统，它负责管理电脑的硬件资源、提供用户界面、运行应用程序等基本功能。对于一个电脑来说，无论登录哪个用户名，操作系统的核心文件和系统设置（如系统内核、驱动程序等）都是相同的。例如，Windows 10操作系统在安装后，其系统文件主要存放在“C:\Windows”目录下，这些文件对于所有用户账户都是共享的，是电脑运行的基础。
	二、用户账户层面
	1.  软件安装
	•  全局安装的软件：有些软件是安装在全局位置的，对所有用户账户都可用。例如，一些系统自带的软件（如Windows自带的计算器、画图工具等）以及一些用户在安装时选择“为所有用户安装”的第三方软件。这些软件的安装路径通常在“C:\Program Files”或“C:\Program Files (x86)”等公共目录下，所有用户登录后都可以使用这些软件。
	•  仅当前用户安装的软件：用户也可以选择仅在自己的用户账户下安装软件。这种情况下，软件的安装路径通常在用户账户的个人目录下，如“C:\Users\用户名\AppData\Local”等位置。例如，用户A在自己的账户下安装了一个特定的文本编辑器，这个软件的配置文件和数据文件都存储在用户A的个人目录下，用户B登录后是无法直接使用这个软件的，除非用户B也单独在自己的账户下安装这个软件。
	2.  操作环境差异
	•  桌面和文件存储：每个用户账户有自己的桌面和文件存储位置。例如，用户A的桌面路径是“C:\Users\用户A\Desktop”，用户B的桌面路径是“C:\Users\用户B\Desktop”。用户在自己的桌面上放置的文件、快捷方式等都是独立的。用户A在自己的桌面上创建的文档，用户B登录后是看不到的，除非用户B有权限访问用户A的个人文件夹。
	•  个性化设置：不同用户账户可以有自己的个性化设置，如屏幕分辨率、主题样式、任务栏设置等。这些设置是存储在用户账户的注册表和个人配置文件中的。当用户登录自己的账户时，操作系统会加载该用户账户的个性化设置，为用户提供个性化的操作体验。例如，用户A喜欢高分辨率的屏幕显示和深色主题，用户B喜欢标准分辨率和浅色主题，当他们分别登录自己的账户时，电脑会根据各自的设置来显示桌面和系统界面。
	•  权限差异：不同用户账户可能有不同的权限。在Windows系统中，有管理员账户和普通用户账户之分。管理员账户拥有较高的权限，可以安装软件、修改系统设置等；普通用户账户的权限相对较低，可能无法安装某些软件或对系统进行重大修改。这种权限差异也会影响用户在电脑上的操作环境。例如，普通用户可能无法访问某些系统文件夹或修改关键的系统设置，而管理员用户则可以自由操作。
	综上所述，虽然电脑的操作系统本身是相同的，但由于用户账户的隔离机制，不同用户登录后，软件的可用性、操作环境（包括桌面、文件存储、个性化设置和权限等）可能会存在差异。这种设计既满足了多用户共享电脑的需求，又保证了每个用户的数据和操作相对独立和安全。

# 环境变量

环境变量的核心作用是
让操作系统和应用程序在全局范围内找到所需的资源和配置，
无需每次都手动指定完整路径。

简单来说，它就像一份 “系统级的快捷方式清单”，主要有这几个作用：

1. **快速定位可执行程序**
    
    比如 Git 的 `git.exe` 被加入 `Path` 环境变量后，你在任意终端里输入 `git`，系统就能自动找到并运行它，不用每次都输入 `C:\Program Files\Git\bin\git.exe` 这么长的路径。
    
2. **传递全局配置信息**
    
    很多软件会通过环境变量读取配置，比如 `JAVA_HOME` 告诉系统 JDK 的安装位置，`PYTHONPATH` 告诉 Python 去哪里找第三方库。
    
3. **统一系统行为**
    
    比如 `TEMP` 环境变量定义了系统临时文件的存放目录，所有程序都遵循这个约定，避免每个程序自己找地方存临时文件。
    
4. **提升开发效率**
    
    在开发场景中，环境变量可以让你在不同终端、不同工具里（比如 VS Code、Git Bash、PowerShell）都能直接调用 Git、Node.js 等工具，不用重复配置路径。

电脑环境变量中的用户变量和系统变量都是用于存储和设置系统运行时所需的各种参数和信息，以便操作系统和应用程序能够正确地运行和找到所需的资源。以下是它们各自的作用： 
## 用户变量 

- **定义**：用户变量是==针对特定用户账户==设置的环境变量。每个用户都可以有自己独立的用户变量设置，这些设置仅对当前用户生效，其他用户登录到同一台计算机时，将使用他们自己的用户变量或默认的系统变量。
- **作用** 
- **个性化配置**：允许用户根据自己的需求和偏好来配置工作环境。例如，用户可以设置特定的文本编辑器或开发工具的路径，以便==在命令行或其他应用程序中方便地调用==。
- **软件特定设置**：某些软件可能会依赖于用户变量来确定其运行时的行为或配置。例如，编程软件可能会使用用户变量来指定项目目录、库文件路径等。
- **用户特定路径**：用户可以通过设置用户变量来添加自己常用的文件或文件夹路径，以便在系统中更便捷地访问这些资源。比如，将个人文档文件夹或常用的工作目录添加到用户变量中，就可以在命令提示符或其他应用程序中直接使用变量名来访问这些路径。 
## 系统变量 
- **定义**：系统变量是对整个计算机系统全局生效的环境变量，它们对所有用户都起作用。系统变量通常在操作系统安装和配置过程中进行设置，并且可以由管理员进行修改和管理。
- **作用** - **系统级配置**：用于指定操作系统和系统组件运行所需的关键信息。例如，系统变量可以指定系统文件的路径、临时文件的存储位置、系统字体的路径等，这些信息对于操作系统的正常运行至关重要。 
- **应用程序支持**：许多应用程序在安装和运行时依赖于系统变量来找到所需的系统资源和库文件。例如，应用程序可能需要访问系统的动态链接库（DLL）文件，而系统变量会告诉应用程序这些DLL文件的存储位置。
- **环境配置**：系统变量可以用于配置整个系统的运行环境，例如设置系统的语言、区域设置、时间格式等。这些设置会影响到所有用户在使用计算机时的环境体验。
- **系统服务和进程**：系统服务和后台进程通常也依赖于系统变量来获取必要的配置信息和资源路径。例如，Windows系统中的任务计划程序可能会使用系统变量来确定要执行的任务的相关文件和路径。
## 环境变量标识

在 Windows 系统里，环境变量是一些具有特定含义的系统设置，它们存储了诸如系统路径、用户信息等数据。为了在命令行或脚本中引用这些环境变量，就需要使用 `%` 符号将变量名括起来。例如：

  

- `%temp%`：代表系统临时文件夹的路径。当你在 “运行” 对话框中输入 `%temp%` 并回车，系统会把 `%temp%` 解析为实际的临时文件夹路径，然后打开该文件夹。
- `%SystemRoot%`：通常指向 `C:\Windows` 目录，这是 Windows 操作系统的根目录。在命令行中输入 `cd %SystemRoot%` ，就会将当前工作目录切换到 `C:\Windows` 。
- `%PATH%`：这个环境变量存储了系统在查找可执行文件时会搜索的一系列目录。当你在命令行中输入一个命令时，系统会按照 `%PATH%` 中指定的目录顺序去查找对应的可执行文件。

## 快捷方式
- **特点**
    - **方便访问**：用户可以在桌面上或其他方便的位置创建快捷方式，通过双击快捷方式就能快速打开对应的目标文件或程序，而无需在众多文件夹中查找原始文件或程序的位置。
    - **可定制性**：用户可以根据自己的需求为快捷方式设置不同的图标，以便更直观地识别。还可以为快捷方式设置快捷键，进一步提高访问效率。
    - **不占用额外空间**：快捷方式本身只是一个指向目标的链接，并不包含目标文件或程序的实际内容，因此占用的磁盘空间非常小。
    - **可移植性**：可以将快捷方式复制或移动到其他位置，甚至是移动存储设备上，只要目标文件或程序在新的环境中能够被访问，快捷方式仍然可以正常使用。
- **创建方式**：在 Windows 系统中，创建快捷方式的方法有多种。例如，在文件或程序的属性中选择 “创建快捷方式”；或者在桌面等位置右键点击，选择 “新建”-“快捷方式”，然后按照向导提示选择目标文件或程序即可。
- **使用场景**
    - **快速启动程序**：对于经常使用的程序，如办公软件、浏览器等，在桌面上创建快捷方式后，用户可以直接双击快捷方式快速启动程序，节省了从开始菜单或安装目录中查找程序的时间。
    - **访问常用文件和文件夹**：对于经常需要访问的文件或文件夹，也可以创建快捷方式并放置在容易找到的位置，方便快速打开。
    - **链接到网页**：可以创建指向网页的快捷方式，将其放在桌面或任务栏上，方便快速访问经常浏览的网站。


## 提醒事项软件
很好问题！答案是：有这样的软件，也可以用闹钟／自动化工具实现一定程度的语音提醒。具体看你用的是 iOS 还是 Android，以及你希望“语音播报提醒”的形式是怎样（是 TTS 读文字？还是播放你录的语音？）。

  

下面是几种实现方案 +推荐软件：

  

  

  

  

一、现成 App 推荐

  

  

  

iOS（iPhone / iPad）

  

  

1. 待辦事項列表 + 語音提醒 (TDLVN)  
    这是一个待办事项 +提醒 +闹钟的 App，你可以用语音记录提醒事项，在到达设定时间时播放。  
2. 行事曆・提醒・筆記與語音備忘錄 (MC Calendar)  
    这款 app 不仅是日历 /待办事项，还支持语音备忘录。  
3. Reminder with Voice Reminders  
    这个 app 支持录自己声音作为提醒，到点后播放。  

  

  

  

  

  

二、Android 方案

  

  

1. Voice Reminder（語音提醒）  
    这个安卓 App 可以让你用语音创建提醒事项，并设置提醒时间。  
2. 使用 Tasker（高级方案）  
    

- Tasker 是一个非常强大的自动化工具，你可以设定“在某个时间触发一个动作”，这个动作可以是“用 TTS（文字转语音）读出提醒内容”。  
    -举例：有人在 Reddit 上用 Tasker，当闹钟触发时执行 “Say” 动作读出标签名字。   
    -这样就能把你写在待办事项里的内容，在提醒时“朗读”出来。

4.   
    
5. Timely Reminder  
    这个闹钟 App 支持文本转语音 (TTS) 功能，会在闹钟触发时用语音读出闹钟名称 /提醒内容。  

  


  

  

三、系统自带 /语音助手

  

  

- Google 助理（Android /iOS）：你可以让 Google Assistant 帮你设定提醒 (“提醒我 XX 时间做 XX”)，它会在设定时间给你通知。  
- iOS 自带提醒事项 App：可以设定时间提醒，但系统默认是通知 +声音，不一定是用语音读出内容。  

  

  

  

  

  

四、总结 +建议

  

  

- 如果你只是想“在某个时间被提醒做某件事”，提醒事项类 App（如 TDLVN、MC Calendar）就很方便。
- 如果你必须用语音读出提醒内容（比如无法看屏幕时听语音提醒），建议使用 Tasker（Android）加上 TTS，或者找支持录音提醒 /语音提醒功能的专门 App（Voice Reminder）。
- 如果你愿意稍微折腾（尤其是 Android），自动化 + TTS 是最灵活、可定制性最高的方法。
