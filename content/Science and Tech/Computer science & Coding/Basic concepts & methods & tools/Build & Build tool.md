# 基本概念
## 认识构建的过程

+ 构建是将源代码转换为可交付使用的软件产物的过程。
+ 构建工具的核心功能之一就是**管理和协调编译器、链接器等工具链**，从而自动化完成项目的构建过程。它并不直接执行编译或链接操作，而是通过生成适配具体工具链的构建脚本（如 Makefile、Visual Studio 项目文件、Ninja 脚本等），间接控制这些工具完成构建。

不同类型的项目（如 C/C++ 项目、Java 项目等）构建环节可能存在差异，但一般来说，构建主要包含以下环节：

### 准备环节

- **环境配置**：确保开发环境中安装了必要的工具，如编译器（针对 C/C++ 的 GCC、Clang，针对 Java 的 javac 等）、构建工具（Make、CMake、Maven、Gradle 等）、版本控制系统（Git、SVN 等 ）。同时，设置好相应的环境变量，让系统能够找到这些工具，例如将 GCC 的安装路径添加到系统的`PATH`环境变量中，使得在命令行中可以直接调用`gcc`命令。
- **依赖管理**：确定项目所依赖的第三方库、框架等资源。通过构建工具的依赖管理功能，自动下载、安装这些依赖。例如在 Java 项目中，使用 Maven 管理依赖时，在`pom.xml`文件中声明项目所需的依赖，如`spring-boot-starter-web`，Maven 会自动从配置的仓库（如 Maven 中央仓库）下载该依赖及其传递依赖；在 C++ 项目中，使用 vcpkg 等工具来管理第三方库的安装和引用。

### 编译环节

此章节内容可参考具体的编译原理[[Compilers principles]]

- **预处理**：对于 C/C++ 等语言，在正式编译前进行预处理操作。预处理器（如`cpp` ）会处理源代码中的预处理指令，如`#include`（将指定的头文件内容插入到当前位置 ）、`#define`（定义宏 ）、`#ifdef`（条件编译 ）等。例如，`#include <stdio.h>`指令会把`stdio.h`头文件的内容复制到源文件中，经过预处理后的文件将作为下一步编译的输入。
- **编译**：编译器（如 GCC、Clang 等）对预处理后的源代码进行词法分析、语法分析、语义分析、代码优化等操作，将高级编程语言编写的代码转换为目标代码，通常是汇编代码或机器码（在不同的编译阶段生成 ）。例如，使用`g++ main.cpp -o main.o`命令，`g++`编译器会把`main.cpp`源文件编译成`main.o`目标文件。
- **代码检查**：在编译过程中，可能会进行代码检查，如静态代码分析。工具（如 Cppcheck、SonarQube 等）会扫描代码，检测潜在的错误（如空指针解引用、内存泄漏隐患 ）、代码风格问题（如不符合指定的编码规范 ）、安全漏洞等，帮助开发者提高代码质量。

### 链接环节

- **目标文件合并**：将编译生成的多个目标文件（`.o`文件）以及相关的库文件组合在一起。链接器（如`ld` ）会解析目标文件中的符号引用，将不同目标文件中相互引用的函数、变量等正确地关联起来。例如，一个 C++ 项目中，`main.o`文件调用了`utils.o`文件中定义的函数，链接器会确保这个调用能够正确执行。
- **库链接**：根据项目需求，链接静态库（`.a`文件，在链接阶段将库中的代码直接复制到可执行文件中 ）或动态库（`.so`文件，在运行时动态加载库 ）。例如，使用`g++ main.o utils.o -o my_program -lm`命令，`-lm`表示链接数学库`libm`，链接器会把数学库中相关的函数代码与目标文件进行链接，最终生成可执行文件`my_program`。

### 测试环节

- **单元测试**：针对程序中的最小可测试单元（如函数、类 ）进行测试。开发者编写测试用例，使用单元测试框架（如 C++ 的 Google Test、Catch2，Java 的 JUnit 等）来验证代码的功能是否正确。例如，在一个计算两个数相加的函数中，通过单元测试可以验证对于不同的输入，函数返回的结果是否符合预期。
- **集成测试**：测试各个模块或组件之间的交互是否正常，验证系统在集成状态下的功能是否符合需求。例如，在一个 Web 应用中，测试不同的 API 接口之间的数据传递和协同工作情况。
- **系统测试**：对整个系统进行全面测试，模拟真实的使用场景，检查系统是否满足功能需求、性能需求、安全需求等。例如，测试一个电商系统在高并发访问下的响应时间、数据一致性等。

### 打包与部署环节

- **打包**：将可执行文件、配置文件、依赖库、文档等相关资源整理成一个可以发布或部署的包。例如，在 Java Web 项目中，使用 Maven 或 Gradle 将项目打包成一个可部署的 WAR 包或 JAR 包；在 C++ 项目中，可能会将可执行文件和相关的动态库等一起打包成一个安装包或压缩包。
- **部署**：将打包好的软件产物部署到目标环境中，如将 Web 应用部署到服务器上，将移动应用发布到应用商店等。在部署过程中，还可能需要进行环境配置、数据库迁移等操作，确保软件在目标环境中能够正常运行。


### 其它
#### 对windows电脑，编译，链接可以用MinGW(以构建C项目为例)

在 Windows 电脑上构建 C 项目，编译、链接环节**并非一定要使用 MinGW**，可以根据实际需求和偏好选择不同工具，具体如下：

##### 使用 MinGW 的情况

- **使用场景**：当你希望在 Windows 系统下使用 GNU 工具链，像 gcc 编译器（用于编译 C 代码）、g++ 编译器（可用于编译 C++ 代码，也能编译 C 代码 ）和对应的链接器（ld）等，同时项目更倾向于遵循 GNU 标准和开源生态时，MinGW 是一个很好的选择。例如，你在开发一个跨平台的开源 C 项目，希望在 Windows 和 Linux 等系统下都能使用类似的编译环境和工具，那么 MinGW 就可以在 Windows 上提供接近 Linux 下 GCC 编译的体验，方便项目的移植和维护。
- **编译示例**：在命令行中，使用`gcc main.c -o main.exe` 命令，MinGW 提供的`gcc`编译器就会对`main.c`源文件进行编译，经过预处理、词法分析、语法分析等步骤生成目标文件，然后链接器会将目标文件和相关库（如 C 标准库 ）链接起来，最终生成可执行文件`main.exe`。

##### 不使用 MinGW 的情况

- **使用 Visual Studio 自带工具**：如果使用 Visual Studio 集成开发环境，它自带了 Microsoft Visual C++ 编译器（cl.exe）和链接器等工具。在 Visual Studio 中创建 C 项目后，通过设置项目属性，选择合适的配置（如 Debug 或 Release ），然后点击构建按钮，Visual Studio 就会调用自带的编译器和链接器对代码进行编译和链接。它能很好地集成 Windows 系统相关的功能和特性，对于开发 Windows 平台特定的应用程序（如 Windows 桌面应用、Windows 服务等 ）很方便。
- **使用 Cygwin**：Cygwin 是一个在 Windows 上模拟类 Unix 环境的工具集，它也提供了 GCC 等编译器以及相关的开发工具。与 MinGW 不同的是，Cygwin 在 Windows 上创建了一个更完整的类 Unix 环境，包含文件系统、进程管理等方面的模拟。当你需要在 Windows 上运行一些依赖类 Unix 环境的 C 项目，或者更习惯在类 Unix 环境下进行开发时，可以选择 Cygwin。
- **使用 LLVM/Clang**：Clang 是 LLVM 项目的一个 C、C++、Objective-C 编译器，也可以在 Windows 上使用。可以通过下载安装 LLVM 工具链，在命令行或其他支持 Clang 的开发环境（如 CLion ）中，使用`clang main.c -o main.exe`命令来编译 C 项目。Clang 以其快速的编译速度、优秀的错误提示信息等特点受到开发者青睐，并且在对 C++ 标准的支持和新特性的跟进上表现出色。

# 学习用CMake

## Cmake语法
### 添加用户库文件

```cmake
# Add sources to executable  
target_sources(${CMAKE_PROJECT_NAME} PRIVATE  
        # Add user sources here  
        Lib/AD7606/Src/ad7606.c  
        Lib/AD7606/Src/Change.c  
)  
  
# Add include paths  
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE  
        # Add user defined include paths  
        Lib/AD7606/Inc  
)
```
